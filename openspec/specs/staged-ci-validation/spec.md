# staged-ci-validation Specification

## Purpose

Гарантировать, что CI сначала независимо собирает поддерживаемые конфигурации, а затем запускает тесты только над успешно собранными артефактами.

## Requirements

### Requirement: Независимые сборки поддерживаемых конфигураций
CI SHALL представлять каждую поддерживаемую пару MCU/модуль как отдельный элемент build-матрицы и собирать только выбранный модуль с его зависимостями.

#### Scenario: Параллельные build-jobs
- **WHEN** workflow запускается для push или pull request
- **THEN** элементы build-матрицы для разных пар MCU/модуль могут выполняться параллельно и имеют отдельный статус

#### Scenario: Неподдерживаемая пара исключена
- **WHEN** модуль не поддерживает определённое семейство MCU
- **THEN** CI не добавляет эту пару в build-матрицу

### Requirement: Тесты зависят от сборки
Каждый CI test-job MUST зависеть от build-job, который произвёл нужную ему конфигурацию, и MUST не запускаться при неуспешной сборке.

#### Scenario: Успешная сборка
- **WHEN** build-job завершается успешно
- **THEN** зависимый test-job получает его сборочные артефакты и запускает тесты для той же пары MCU/модуль

#### Scenario: Ошибка сборки
- **WHEN** build-job завершается с ошибкой или отменяется
- **THEN** зависимый test-job не запускается

### Requirement: Сборка не запускает тесты
Этап сборки MUST только конфигурировать и компилировать цели; выполнение unit-, hardware- и Renode-тестов MUST происходить только на этапе тестирования.

#### Scenario: Сборка цели с зарегистрированными тестами
- **WHEN** build-job компилирует конфигурацию, для которой определены тесты
- **THEN** ни один тестовый процесс не запускается как побочный эффект обычной сборки

### Requirement: CI запускает только применимые тесты
CI SHALL создавать test-job только для пар MCU/модуль, для которых в репозитории существует автоматизированный тест, пригодный для CI-окружения.

#### Scenario: Модуль без CI-теста
- **WHEN** build-матрица содержит пару MCU/модуль, для которой нет автоматизированного CI-теста
- **THEN** CI проверяет её сборку и не создаёт пустой test-job

### Requirement: Результаты матрицы видимы отдельно
CI SHALL показывать в видимом имени каждого элемента матрицы тип этапа, семейство MCU и модуль.

#### Scenario: Ошибка одного модуля
- **WHEN** один элемент build- или test-матрицы завершается с ошибкой
- **THEN** из имени job в виде workflow можно однозначно определить этап, MCU и модуль
